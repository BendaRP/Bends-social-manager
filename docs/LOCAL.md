# הרצה על המחשב שלך

המדריך בנוי כארבעה שלבים. **כל שלב עומד בפני עצמו ומסתיים במשהו שאפשר לראות** —
אפשר לעצור אחרי כל אחד מהם ולחזור למחרת.

**חשוב לדעת מראש:** כל עוד המערכת רצה על המחשב שלך, פוסט מתוזמן יפורסם רק אם
המחשב דלוק והתוכנה רצה. פוסט שתזמנת ל-7 בבוקר לא ייצא אם המחשב ישן. זה בסדר
לשלב הבדיקות — כשתרצה תזמון אמיתי, נעביר לענן.

---

## שלב 0 — המערכת רצה אצלך (‏~20 דקות)

**מה תראה בסוף:** מסך התחברות, לוח בקרה, יומן תוכן ריק. עדיין בלי חיבור לרשתות.

### 1. להתקין Node.js

<https://nodejs.org> — לבחור את גרסת **LTS**. זה הדבר היחיד שחייבים להתקין.

### 2. להוריד ולהריץ

לפתוח טרמינל (‏במק: Terminal · בווינדוס: PowerShell) ולהדביק שורה-שורה:

```bash
git clone https://github.com/BendaRP/Bends-social-manager.git
cd Bends-social-manager
npm run setup
```

האשף יזהה לבד מה זמין במחשב שלך ויציע את המסלול המתאים.

### בסיס הנתונים — שני מסלולים

המערכת צריכה שני שירותים ברקע: **Postgres** (שומר את הפוסטים והנתונים)
ו-**Redis** (מנהל את תור הפרסום). יש שתי דרכים להשיג אותם, והאשף בוחר לבד:

#### מסלול א' — Docker (אם הוא עובד אצלך)

אם **Docker Desktop** מותקן ופועל, האשף ירים את שניהם מקומית ולא תצטרך לעשות כלום.
להורדה: <https://docker.com/products/docker-desktop>

#### מסלול ב' — ענן חינמי (אם Docker לא עובד)

> **אם קיבלת את השגיאה `Virtualization support not detected`** — זו לא בעיה בקוד.
> ‏Docker Desktop דורש וירטואליזציה, והיא כבויה ב-BIOS או חסומה במדיניות של מקום העבודה.
> **פשוט תדלג על Docker** ולך במסלול הזה. התוצאה זהה לחלוטין.

האשף יבקש ממך שתי כתובות. שתיהן הרשמה חינמית, בלי כרטיס אשראי, בלי התקנה:

**‏א. Postgres — ‏Neon**
1. <https://neon.tech> → הרשמה (אפשר עם חשבון Google)
2. ליצור פרויקט חדש
3. להעתיק את ה-**Connection string** — מתחיל ב-`postgresql://`

**‏ב. Redis — ‏Redis Cloud**
1. <https://redis.io/try-free> → הרשמה
2. ליצור מסד חדש בתוכנית **Free (30MB)**
3. להעתיק את ה-**Public endpoint** ואת הסיסמה, ולהרכיב כתובת בצורה:
   `redis://default:הסיסמה@הכתובת:הפורט`

להדביק כל אחת מהן כשהאשף מבקש. **האשף בודק את החיבור מיד** — אם הדבקת משהו שגוי,
תדע על זה תוך שניות ולא בפרסום הראשון.

> **למה דווקא Redis Cloud:** יש שירותי Redis חינמיים אחרים, אבל חלקם מגבילים את
> מספר הפקודות היומי. תור העבודות שולח הרבה פקודות קטנות ברקע ועלול לחרוג מהמכסה,
> ואז פוסטים מתוזמנים פשוט יפסיקו לצאת בלי הודעה. ל-Redis Cloud אין מגבלה כזו.

### 3. להפעיל

בסוף האשף ישאל אימייל וסיסמה למשתמש שלך. **שמור את הסיסמה במנהל סיסמאות.** ואז:

```bash
npm run dev:all
```

לפתוח בדפדפן: <http://localhost:3000>

> **מה זה `dev:all`:** מפעיל שני תהליכים במקביל — הממשק, ותהליך הפרסום שמתעורר
> בזמנים המתוזמנים. **בלי השני, פוסטים מתוזמנים לא יפורסמו.** אל תסגור את החלון.

## שלב 1 — הפוסט הראשון לפייסבוק (‏~40 דקות)

**מה תראה בסוף:** פוסט טקסט אמיתי על עמוד הפייסבוק שלך, שיצא מהמערכת אחרי שאישרת אותו.

התחלנו דווקא בפייסבוק ובטקסט בלבד **כי זה המסלול הקצר ביותר להוכחה שהמערכת עובדת** —
בלי אחסון תמונות, בלי טיקטוק, בלי המתנה לאישורים.

### 1. כתובת אינטרנט זמנית

‏Meta מסרבת להתחבר לכתובת מקומית ודורשת HTTPS. בטרמינל **חדש** (‏להשאיר את
הקודם רץ):

```bash
npx cloudflared tunnel --url http://localhost:3000
```

יופיע משהו כמו `https://random-words-here.trycloudflare.com`. **להעתיק אותה.**

> הכתובת משתנה בכל הפעלה של המנהרה. אם תסגור ותפתח מחדש — צריך לעדכן אותה
> ב-`.env` ואצל Meta. מעצבן, אבל זמני.

### 2. עדכון הכתובת ב-‏`.env`

לפתוח את הקובץ `.env` (‏בעורך טקסט רגיל) ולשנות:

```
APP_URL="https://הכתובת-שקיבלת.trycloudflare.com"
```

### 3. אפליקציית מפתחים ב-Meta

הפירוט המלא ב-[`SETUP.md`](SETUP.md) שלבים א'–ב'. בקצרה:

1. אינסטגרם שלך → חשבון **Business** → מקושר לעמוד פייסבוק
2. <https://developers.facebook.com/apps> → **Create App** → סוג **Business**
3. הוספת **Facebook Login for Business**
4. ב-Redirect URIs להדביק: `https://הכתובת-שלך/api/auth/meta/callback`
5. **App Roles → Add People → Instagram Tester** — להזמין את עצמך,
   **ולאשר את ההזמנה מתוך אינסטגרם** (‏הגדרות → אפליקציות ואתרים)
6. **App Settings → Basic** — להעתיק `App ID` ו-`App Secret` ל-`.env`

> **למה Tester:** כל עוד מחוברים רק החשבונות שלך, האפליקציה נשארת במצב
> Development ואין צורך ב-App Review. זה מה שחוסך שבועות המתנה.

### 4. לחבר ולפרסם

להפעיל מחדש (‏`Ctrl+C` ואז `npm run dev:all`), ואז בממשק:

1. **חשבונות מחוברים** → חיבור Meta
2. **פוסט חדש** → פורמט **טקסט בלבד** → לכתוב משהו → לבחור את עמוד הפייסבוק → שמירה
3. **ממתין לאישור** → **אישור לפרסום**

הפוסט אמור להופיע על העמוד תוך שניות. **אם זה עבד — המערכת עובדת.** כל השאר תוספות.

## שלב 2 — תמונות ואינסטגרם (‏~30 דקות)

**מה תראה בסוף:** תמונה מתפרסמת לאינסטגרם.

אינסטגרם לא מקבל פוסט טקסט, וגם לא מקבל העלאת קובץ ישירות: **הוא מקבל כתובת
ומוריד את התמונה בעצמו, מהשרתים שלו.** לכן צריך מקום ציבורי לאחסן תמונות.

1. <https://dash.cloudflare.com> → **R2** → יצירת דלי (יש שכבה חינמית נדיבה)
2. **Settings → Public access** → להפעיל
3. **Manage API Tokens** → טוקן עם הרשאת **Object Read & Write**
4. למלא ב-`.env`: `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`,
   `S3_SECRET_ACCESS_KEY`, `S3_PUBLIC_BASE_URL`
5. `npm run check` — מוודא שהכל תקין לפני שסומכים על זה

> **הטעות הנפוצה:** דלי פרטי יעבוד מצוין מהדפדפן שלך וייכשל בכל פרסום, כי
> אינסטגרם ניגש אליו בלי שום הרשאה. המערכת בודקת את זה בזמן ההעלאה כדי שתגלה
> את הבעיה כשאתה מול המסך.

## שלב 3 — טיקטוק (‏~20 דקות)

**מה תראה בסוף:** סרטון בטיקטוק — **גלוי רק לך**.

1. <https://developers.tiktok.com/apps> → אפליקציה חדשה
2. מוצרים: **Login Kit** + **Content Posting API** (‏להפעיל **Direct Post**)
3. Redirect URI: `https://הכתובת-שלך/api/auth/tiktok/callback`
4. **URL Properties** → לאמת את הדומיין של האחסון — **בלי זה כל פרסום ייכשל**
5. להעתיק `Client Key` ו-`Client Secret` ל-`.env`
6. **להעביר את חשבון הטיקטוק למצב פרטי** — נדרש כל עוד לא עבר Audit

זכור: עד שאפליקציית ה-API תעבור **Audit**, כל פוסט יהיה Self-only, ופוסטים
מהתקופה הזו **לא יהפכו לציבוריים רטרואקטיבית** — יהיה צריך לפרסם אותם מחדש.

## יצירת תוכן ב-AI (שלב 4)

1. להוציא מפתח ב-<https://console.anthropic.com/settings/keys>
2. להוסיף ל-`.env`: `ANTHROPIC_API_KEY="sk-ant-..."`
3. פעם אחת בלבד: `npx playwright install chromium` — זה מנוע העיצוב שמרנדר את שקופיות הקרוסלה
4. להפעיל מחדש, ולמלא את **זהות המותג** בתפריט

אחרי זה יופיע בעמוד "פוסט חדש" כפתור **לכתוב את הפוסט עם AI**.

> **השדה שהכי משפיע על התוצאה** הוא "מילים לאסור" בזהות המותג. שם רושמים את
> הקלישאות של התחום שלכם — בלעדיו המודל יגיע אליהן מעצמו, כי הן נפוצות בכל מה
> שנכתב על התחום.

**גם תוכן שנוצר ב-AI עובר את שער האישור.** הוא נשמר כטיוטה, אתה עורך אותה כרצונך,
ורק אישור מפורש שלך מוציא אותה לאוויר.

## תקלות נפוצות

**‏`Virtualization support not detected` ב-Docker**
‏Docker Desktop דורש וירטואליזציה, שכבויה ב-BIOS או חסומה במקום העבודה.
לא צריך לפתור את זה — לדלג על Docker וללכת במסלול הענן החינמי בשלב 0.

**‏`npm run setup` נכשל על Docker אף שהוא מותקן**
‏Docker Desktop לא פתוח. לפתוח אותו, לחכות שהאייקון יתייצב, ולהריץ שוב —
או פשוט לסגור אותו לגמרי, ואז האשף יציע את מסלול הענן.

**רוצה לעבור ממסלול Docker לענן (או להפך)**
לערוך את `DATABASE_URL` ו-`REDIS_URL` בקובץ `.env`, ולהריץ שוב `npm run setup`.

**פוסט מתוזמן לא פורסם**
לוודא ש-`npm run dev:all` רץ (‏שני תהליכים, לא רק אחד), ושהמחשב לא נכנס לשינה.

**‏`Invalid Scopes: instagram_content_publish, ...` בעת החיבור**
האפליקציה ב-Meta עדיין לא הפעילה את ההרשאות האלה. זו הגדרה בדשבורד, לא באג.
ב-<https://developers.facebook.com/apps> → האפליקציה שלך → **Use cases** →
ליד כל Use case ללחוץ **Customize** → לשונית **Permissions** → **Add** ליד
ההרשאה החסרה. אחרי ההוספה לנסות לחבר שוב.

כדי להתקדם בינתיים אפשר לצמצם זמנית את רשימת ההרשאות ב-`.env`:
```
META_SCOPES="instagram_basic,pages_show_list,pages_read_engagement"
```
זה מאפשר להשלים את החיבור ולוודא שהכל עובד. **בהרשאות המצומצמות עדיין אי אפשר
לפרסם** — כשההרשאות המלאות יופעלו בדשבורד, למחוק את השורה ולהתחבר מחדש.

**החיבור הצליח אבל אין חשבונות אינסטגרם**
עמודי הפייסבוק חוברו ואפשר לפרסם אליהם. לאינסטגרם צריך שהחשבון יהיה
**Business** או **Creator** ושיהיה מקושר לעמוד: הגדרות העמוד ← "חשבונות מקושרים"
← Instagram. אחרי הקישור לחבר כאן מחדש.

**‏"לא נמצא אף עמוד פייסבוק בחשבון הזה"**
או שבמסך ההרשאות של פייסבוק לא סימנת אף עמוד (להתחבר שוב ולוודא שהעמוד מסומן),
או שאינך מנהל של אף עמוד עסקי. לבדוק ב-<https://www.facebook.com/pages/?category=your_pages>

**החיבור נכשל אחרי שסגרתי את המנהרה**
כתובת ה-cloudflared השתנתה. לעדכן ב-`.env` ובהגדרות Meta.

**`לא ניתן להפעיל את מנוע העיצוב (Chromium)`**
להריץ פעם אחת: `npx playwright install chromium`

**לבדוק מה תקין ומה לא**
```bash
npm run check
```
