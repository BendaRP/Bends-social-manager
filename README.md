# מנהל הסושיאל

מערכת לניהול הנוכחות העסקית באינסטגרם, בפייסבוק ובטיקטוק: יצירת תוכן, תזמון,
פרסום עם אישור ידני, ואיסוף נתוני ביצועים.

**להתחלה מהירה על המחשב שלך: [`docs/LOCAL.md`](docs/LOCAL.md)**
**מדריך ההקמה המלא של כל הפלטפורמות: [`docs/SETUP.md`](docs/SETUP.md)**

```bash
git clone https://github.com/BendaRP/Bends-social-manager.git
cd Bends-social-manager
npm run setup      # מייצר מפתחות, מתקין, מחבר בסיס נתונים, יוצר משתמש
                   # (עובד עם Docker מקומי או עם בסיס נתונים בענן — לבחירתך)
npm run dev:all    # מפעיל את הממשק ואת תהליך הפרסום יחד
```

## עקרונות

**אישור ידני הוא בדיקה בקוד, לא הגדרה בממשק.**
`publishTarget` מסרב לפעול על פוסט שאיש לא אישר. אין דגל, אין עקיפה מנהלתית,
ואין פרמטר `force`. הבדיקה מכוסה בטסטים ב-`tests/approval-gate.test.ts`.

**מגבלות נשלפות מהפלטפורמה, לא מקובעות בקוד.**
המקורות הפומביים לגבי מגבלת הפרסום של אינסטגרם סותרים זה את זה, ולכן המערכת
שואלת את החשבון עצמו לפני כל פרסום. ראה [`docs/API-VERIFICATION.md`](docs/API-VERIFICATION.md).

**נתוני הלמידה נאספים מהיום הראשון.**
מנוע ההמלצות של שלב 3 יוכל לנתח רק מה שנשמר בשלב 1. לכן כל פרסום כותב כבר עכשיו
שורת מאפיינים (`PostFeatures`) ותמונות מצב של ביצועים (`MetricSnapshot`),
גם ששום מסך עדיין לא מציג אותן.

**רק ממשקי API רשמיים.** בלי סקרייפינג, בלי בוטים, בלי engagement pods.

## ארכיטקטורה

```
דפדפן ─► Next.js (ממשק + API) ─► PostgreSQL
                │                      ▲
                ▼                      │
          Redis + BullMQ ─► תהליך עובד ─┘─► PlatformAdapter ─► Meta / TikTok
                                                    │
                                       אחסון תואם-S3 (Cloudflare R2)
```

**שני תהליכים נפרדים.** הממשק מגיב לבקשות; תהליך העובד רץ ברציפות ומתעורר בעצמו
לפרסם בזמנים המתוזמנים. בלי התהליך השני אין תזמון.

**`PlatformAdapter`** הוא התפר בין "מה לפרסם" לבין "איך כל רשת רוצה לשמוע על זה".
כל הייחודיות של כל רשת נעולה בתוך המימוש שלה — מה שמאפשר להחליף מימוש (למשל
להעביר את טיקטוק לספק צד שלישי עד שה-Audit יאושר) בלי לגעת בשאר המערכת.

## אבטחה

- טוקני OAuth מוצפנים ב-AES-256-GCM בבסיס הנתונים; המפתח הראשי במנהל הסודות של שירות האירוח
- הרשאות מינימליות בלבד — ראה `src/platforms/meta/scopes.ts` לרשימה ולנימוק לכל אחת
- טוקנים מוסתרים מכל לוג ומכל רשומת שגיאה (`redactSecrets`)
- הגבלת קצב על טופס ההתחברות; אסימוני סשן נשמרים כ-hash בלבד
- שני מגבילי קצב לפרסום: המכסה החיה של הפלטפורמה, ותקרה שמרנית משלנו
